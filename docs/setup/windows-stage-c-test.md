# Windows acceptance: stage C

Branch: `codex/windows-hotkeys-paste`. Keep it separate from main until physical
Windows tests pass. Install the package again after every pull; source checkout
alone does not update your installed CLI.

## Install

Finish recording and close the old host. In the repository's PowerShell:

```powershell
git fetch --prune origin
git switch --track origin/codex/windows-hotkeys-paste
.\.venv\Scripts\python.exe -m pip install ".[whisper,hotkeys]"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\dictate.exe --unload-model
.\.venv\Scripts\voice-hotkeys.exe --hotkey-modifiers alt+shift
```

If the branch exists, use `git switch codex/windows-hotkeys-paste` then
`git pull --ff-only`. Substitute `venv` if that is your environment's folder.
Current suite: 48 tests; tests for other operating systems are skipped normally.
Windows installs `comtypes` automatically for UI Automation field verification.

## Quick test without a model

Close the host for this isolated check:

```powershell
.\.venv\Scripts\python.exe scripts/check_paste.py
```

Press **Test native paste**, then do not move focus until the result appears.
PASS requires exact Unicode text inserted once in the test field and focus retained.
The test puts synthetic text into your clipboard; it does not record audio.
If it fails, send the displayed error. A successful SendInput call alone does not
count as a passed GUI test.

## Main matrix

Open Notepad, Chrome/Edge with a multiline text field, and VS Code with an unsaved
plain-text document. Keep editor indentation/autocomplete effects separate from
extra text generated by the dictation app. Do not send any messages automatically.

For each app, test EN and UK keyboard layouts:

| Action | Steps | Expected |
| --- | --- | --- |
| U | Alt+Shift+U, Ukrainian phrase, U again, wait | No extra U/Ю; field unchanged until manual Ctrl+V |
| E | Alt+Shift+E, English phrase, E again, wait | No extra E; clipboard contains English; no automatic paste |
| L | Place caret, Alt+Shift+L, speak, L again, wait | No extra L/Л; transcript inserted once at the caret |
| L → U/E | Start L; stop U or E | Original Ukrainian copy+paste action preserved |
| U/E → L | Start U or E; stop L | Copy only; no automatic paste |

Repeat each action 20 times in your primary editor. No duplicate text, automatic
Enter, extra recording processes or stuck modifiers. After testing, ordinary U/E/L,
Shift+letters, Ctrl+C/V and Alt+Tab must still work normally.

## Edge cases

1. Hold the start shortcut for two seconds: one recording only, no auto-repeat stop.
   Release all keys, then press again to stop. Repeat with left/right Alt and Shift.
   Right Alt may act as AltGr depending on keyboard layout; note the exact layout.
2. Press start then stop quickly while the child/model is starting. No second
   recording should launch; a short/empty recording may produce no transcript.
3. Start L, stop it, keep Alt/Shift held while transcription finishes. If released
   within the two-second paste wait, paste may proceed; otherwise clipboard only
   with a release-modifiers/manual-paste message. No forced key release.
4. Start L, switch to another window or another field, then stop. Text must NOT
   be pasted there. The clipboard must contain the transcript; paste manually.
5. Switch away and return before stopping: once the monitor observes a target
   change, that session stays clipboard-only. Very brief changes between polling
   samples are an inherent observation limit; report any unexpected paste.
6. Close the original target window during recording. No paste into the next
   foreground window, no crash; clipboard remains usable.
7. Click elsewhere in the same field: we do not restore a saved caret. Windows
   tracks field identity, so insertion may occur at the new caret in that same
   unchanged field. Switching to a different field must block automatic paste.
8. Change clipboard content while waiting for modifiers to be released. The app
   must not paste that unrelated content. Recover the transcript with
   `dictate.exe --copy-last`, then paste manually.
9. Test an elevated editor while voice-hotkeys runs normally. UIPI or inaccessible
   field identity can prevent injection: clipboard-only with an explanation is
   correct. Do not make running the host as administrator your default workaround.
10. Repeat with cold/warm models and CUDA. Ctrl+C/drain from stage B must still work.

## Layout conflicts and shortcut settings

The host warns when its modifiers overlap the Windows layout-switch setting;
it never changes Windows keyboard preferences. RegisterHotKey conflicts fail with
an explicit message and release any registrations already made.

If Alt+Shift changes the input language or conflicts with another app, stop the host:

```powershell
.\.venv\Scripts\voice-hotkeys.exe --hotkey-modifiers ctrl+alt
```

Now use Ctrl+Alt+U/E/L. The setting is saved only after successful registration.
Restart without the flag to verify persistence. Restore the default with
`--hotkey-modifiers alt+shift`. Preferences live in the app's `settings.json` under
`%LOCALAPPDATA%\VoiceToClipboard`; they are separate from transcript history.

Launching a second host should report that one is already running. To test an
actual OS registration conflict, have another shortcut application reserve the
same combination, then start this host; do not change system shortcuts for testing.
